# Roadwits — клиент

Tauri 2 + чистый HTML/CSS/JS (ES-модули, без сборщика). Кросс-платформенно:
Windows, macOS, Linux, Android, iOS — один и тот же frontend на всех.

## Требования

- Rust + `cargo`
- Tauri CLI: `cargo install tauri-cli --version "^2.0"`
- Системные зависимости под конкретную платформу: https://tauri.app/start/prerequisites/
  (для Android — Android Studio + SDK/NDK, для iOS — Xcode, оба нужны отдельно от базовых desktop-требований)

## Запуск (desktop)

```bash
cd src-tauri
cargo tauri dev
```

Бэкенд (`roadwits-server`) должен быть поднят отдельно на `localhost:8000`
(см. `src/js/api.js` — `API_BASE_URL`, поменяй под себя при необходимости).
CORS на бэкенде уже открыт (`CORS_ORIGINS=*` в его `.env`) — специально
настраивать под `tauri://localhost`/`http://tauri.localhost` не нужно.

## Сборка (desktop)

```bash
cd src-tauri
cargo tauri build
```

## Android / iOS

Нативные Android/iOS-проекты (`src-tauri/gen/android`, `src-tauri/gen/apple`)
в этом архиве **не сгенерированы** — для них нужны Android SDK/NDK и Xcode
соответственно, которых нет в среде, где писался этот код. Сделать это можно
только руками, на своей машине:

```bash
cargo tauri android init
cargo tauri android dev      # или build

cargo tauri ios init
cargo tauri ios dev          # или build
```

Иконки под обе платформы уже лежат в `src-tauri/icons/android/` и
`src-tauri/icons/ios/` (сгенерированы заранее через `cargo tauri icon`) —
`init` должен подхватить их сам.

### Альбомная ориентация на телефоне/планшете

Приложение должно быть только горизонтальным (см. "Горизонтальная ориентация"
ниже) — на мобильных это настраивается на уровне нативного проекта, не через
`tauri.conf.json` (там такого поля нет). Сделать **после** `init`:

**Android** — `src-tauri/gen/android/app/src/main/AndroidManifest.xml`,
у `<activity>` (обычно `MainActivity`) добавить:
```xml
android:screenOrientation="landscape"
```

**iOS** — `src-tauri/gen/apple/.../Info.plist`, оставить в
`UISupportedInterfaceOrientations` (и `~ipad` варианте) только
`UIInterfaceOrientationLandscapeLeft` / `UIInterfaceOrientationLandscapeRight`,
убрав портретные значения.

Пока это не сделано (или на случай, если где-то забудут), в самом приложении
есть CSS-заглушка: если открыть его на тач-устройстве в портретной
ориентации, поверх всего показывается экран «Поверни устройство
горизонтально» (`#rotate-overlay`, чистый CSS `@media (pointer: coarse) and
(orientation: portrait)`, JS не участвует) — так что даже без нативной
блокировки приложение не будет ломаться визуально, а прямо попросит повернуть.

## Как это устроено

### Frontend без сборщика

`tauri.conf.json` → `frontendDist: "../src"` — статика напрямую, никакого
Vite/Deno/npm. `src/js/main.js` подключен как `<script type="module">`,
остальные файлы — обычные ES-модули с `import`/`export`, это работает из
коробки в любом современном webview без транспиляции.

### Почему сплэш — оверлей внутри окна, а не отдельное Tauri-окно

Раньше было два `tauri.conf.json`-окна: `splash` (показывалось сразу) и
`main` (скрытое, `visible: false`), и в `lib.rs` — поток с `sleep(2s)`,
который закрывал `splash` и показывал `main`. Проблемы:

1. Задержка была фиксированной (2 секунды вникуда), не привязанной к
   реальной готовности — автологин мог занять и меньше, и больше времени.
2. Многооконность на Android/iOS в Tauri v2 поддерживается не так, как на
   десктопе — второе окно там лишний риск, которого проще не иметь вообще.

Теперь `tauri.conf.json` описывает **одно** окно (`main`, `visible: true`
сразу), а сплэш — обычный `<div id="splash-overlay">` поверх всего в
`index.html`. `main.js` прячет его (`render.hideSplash()`) сразу после того,
как `auth.tryAutoLogin()` реально решил — показывать логин или сразу
приложение. Работает одинаково на всех платформах, без второго окна.

### Хранение сессии — свои Rust-команды, не `tauri-plugin-store`

У `tauri-plugin-store` JS-биндинги рассчитаны на npm-пакет, а здесь чистый
JS без сборщика. Вместо плагина — три команды в `src-tauri/src/lib.rs`,
вызываемые из `src/js/device.js` через `window.__TAURI__.core.invoke(...)`:

- `get_fingerprint` — стабильный UUID устройства, генерируется один раз
- `save_token` / `load_token` / `clear_token` — JWT

Всё лежит в одном JSON-файле в `app_data_dir()` (путь зависит от ОС и
управляется самим Tauri, работает одинаково на всех пяти платформах).

### Структура JS — по слоям, не по экранам

```
src/js/
  state.js     — общий объект состояния, без функций
  api.js       — весь HTTP к бэкенду + приведение его ответов к внутренней форме
  device.js    — Tauri invoke, управление окном, отключение поведений сайта
  render.js    — единственное место, которое пишет в DOM
  quiz.js      — бизнес-логика: подбор вопросов, подтверждение ответа, таймер,
                 подсчёт результата, навигация по меню/главам, профиль
  admin.js     — CRUD глав/вопросов/лицензий для editor/admin: строит формы
                 модалки, сам же вешает на них обработчики submit
  auth.js      — orchestration логина: связывает api+device+render
  controls.js  — клавиатура, мышь/тач, маска ввода Product Key
  main.js      — точка входа, только вызывает остальное в нужном порядке
```

Правило простое: `quiz.js`/`auth.js` меняют `state` и зовут функции
`render.js` — сами DOM не трогают. `render.js` ничего не решает — просто
рисует то, что в `state`. `controls.js` не содержит бизнес-логики — только
"какая клавиша/клик что вызывает".

### Структура CSS — по слоям, не по экранам

```
src/css/
  main.css        — единственный файл, подключённый в HTML; просто @import остальных
  reset.css       — сброс браузерных дефолтов + отключение поведений сайта
                    (выделение текста мимо полей ввода, скролл страницы целиком)
  variables.css   — вся тема: палитра, шрифты, размеры; смена темы — правки только тут
  layout.css      — структура: что где расположено (титлбар, сцена, split-панели)
  components.css  — оформление конкретных элементов (кнопки, карточки, галочки и т.д.)
```

Раньше у экрана логина и у экрана-тренажёра были разные, не связанные между
собой палитры (синий акцент vs амбер/красный/зелёный). Теперь тема одна —
взята предметная (светофорные цвета — это буквально приложение про ПДД),
и кнопки титлбара (закрыть/свернуть/развернуть) теперь используют те же три
цвета, что и индикатор состояния и датчик результата — раньше это было
совпадением, теперь осознанное единое решение.

### Мышь и клавиатура работают вместе, не взаимоисключающе

- **Меню / список глав**: клик мышью по строке — то же самое, что стрелки
  (просто выбор/просмотр); чтобы стартовать главу мышью — отдельная кнопка
  «Начать тренировку» в панели деталей (клавиатура делает это через Enter).
- **Варианты ответа**: клик мышью сразу фиксирует ответ и раскрывает цвета
  (правильный/неправильный) — это уже однозначное действие. С клавиатуры
  цифра **только подсвечивает** вариант, а `Enter`/`Space` подтверждает и
  раскрывает цвета — так меньше риска промахнуться мимо клавиши и случайно
  зафиксировать не тот ответ. В exam-режиме цвета не раскрываются никогда
  (как и раньше), поэтому там и с клавиатуры фиксация мгновенная.
- Список вариантов ответа теперь скроллится сам (`overflow-y: auto` на
  `.q-options`), если вопросов много и они не помещаются по высоте — текст
  вопроса и итоговая строка ответа остаются на месте, скроллится только сам
  список.

### Горизонтальная ориентация

- **Desktop**: `tauri.conf.json` → `minWidth: 860, minHeight: 520,
  maxHeight: 900` — не даёт окну стать ни маленьким, ни портретным по одним
  только границам. Дополнительно `device.js` → `enforceLandscapeWindow()`
  слушает `onResized` и живьём поправляет размер, если высота вдруг обогнала
  ширину (растягивали только нижнюю границу). Это лучшее из доступного на
  уровне Tauri v2 JS API, не гарантия на уровне ОС.
- **Mobile**: см. раздел "Android / iOS" выше — блокировка на уровне
  нативного манифеста (после `init`) + CSS-заглушка на случай, если она ещё
  не настроена.

### Тач-устройства не показывают то, что им не нужно

`device.js` → `isTouchDevice` (`matchMedia("(pointer: coarse)")`) решает, что
на телефоне/планшете не нужно: кнопки управления окном (`.window-buttons`,
скрыты через `@media (pointer: coarse)`) и подсказки по клавишам внизу
(`.hint-bar`, скрыт так же) — на тач-устройстве нет ни оконного режима, ни
физической клавиатуры по умолчанию. `main.js` также не навешивает
`initWindowControls()`/`enforceLandscapeWindow()` на тач-устройствах — там
эти API либо не имеют смысла, либо могут просто не существовать.

## Найденные и исправленные баги при переносе

- **`build.rs` лежал в `src-tauri/capabilities/`, а не в `src-tauri/`** —
  Cargo ищет build-скрипт рядом с `Cargo.toml` по конвенции; в старом месте
  он не находился, и `tauri_build::build()` (генерация Tauri-контекста)
  просто не запускался бы. Перенесён в корень `src-tauri/`.
- **Не было `#[cfg_attr(mobile, tauri::mobile_entry_point)]`** над `run()` в
  `lib.rs` — обязательный атрибут для сборки под Android/iOS в Tauri v2, без
  него мобильные таргеты не соберутся. Добавлен.
- **Enter на экране логина проваливался в глобальный обработчик клавиш** и
  уходил в `case "menu"` (открывал главы прямо с экрана логина, хотя
  человек ещё не вошёл) — потому что `state.screen` по умолчанию равен
  `"menu"` даже до авторизации. Теперь обработчик клавиатуры в первую же
  строку проверяет, скрыт ли `#login-view`, и если нет — не перехватывает
  вообще ничего, отдавая Enter форме логина как обычный submit.

## Реализовано

- Экран логина — ввод Product Key, вход по Enter как обычный submit формы
- Автологин при следующих запусках по сохранённому токену
- Если токен истёк / лицензия заблокирована (401 от `/auth/me`) — токен
  сбрасывается, снова экран логина
- После входа — весь тренажёр: меню режимов, главы (с описанием и
  количеством вопросов — источник правды в бэкенде, не хардкод), прохождение
  теста (по главе / случайный билет / экзамен с таймером), результат с
  разбором ответов
- Аватар (инициалы + цвет по id — бэкенд не хранит фото, см. ниже) и имя в
  титлбаре, клик по нему открывает страницу профиля (email, роль, срок
  лицензии, статус)
- **editor/admin** видят кнопки редактирования прямо в интерфейсе:
  - главы: ➕ добавить (только admin), ✏️ переименовать, режим
    редактирования (переключатель) открывает ❌ удалить (только admin)
  - вопросы внутри главы: ➕ добавить, ✏️ редактировать (текст, подсказка,
    фото, варианты ответа с отметкой правильного), ❌ удалить — форма в
    единой модалке, не отдельным экраном
  - **admin** дополнительно видит на своей странице профиля панель
    администрирования: список лицензий, продление на 30 дней,
    блокировка/разблокировка, выдача новой лицензии
- Полностью на клавиатуре ИЛИ полностью на мыши/тач — оба способа
  равноценны, не приходится переключаться

### Про фото профиля

В `User` на бэкенде (`roadwits-server/app/models/user.py`) нет поля под
изображение — только текстовые/JSON-поля (`email`, `settings`,
`payment_info` и т.п.). Аватар поэтому — инициалы на цветном фоне
(цвет детерминированно считается от `user.id`, не рандомится при каждом
рендере). Если на бэкенде появится реальное поле под фото — единственное
место в клиенте, которое нужно будет поменять на `<img>`, это
`initialsOf()`/`renderAccountChip()`/`renderProfile()` в `render.js`.

### Про отсутствие обрезания и использование пространства

- `.screen` теперь сам скроллится (`overflow-y: auto`), если контента
  больше, чем высоты окна — раньше в таком случае контент просто пропадал
  за нижней границей без возможности до него докрутить (актуально на
  невысоких окнах и телефонах в альбомной ориентации).
- Ширина экранов больше не зашита в фиксированный `px`-потолок — теперь
  `min(N px, M vw)`: на большом мониторе используется больше доступного
  места, на маленьком — не вылезает за viewport.

## Слияние с параллельной веткой (тренажёр)

Перенёс из параллельно разработанной версии (обычный сайт-тренажёр без Tauri):

- **Мультивыбор глав** — чекбокс на каждой главе (`Space` или клик по ☐),
  можно отметить несколько и пройти тест сразу по ним. Раньше backend не
  отдаёт вопросы "по нескольким главам разом" одним запросом — тянем
  вопросы каждой отмеченной главы параллельно и объединяем на клиенте
  (`quiz.beginQuiz("chapter", [chapters])`).
- **Выбор количества вопросов** для случайного билета — отдельный экран
  (5/10/20/30), а не жёстко зашитые 5.
- Кнопки навигации по вопросам мышью (позже заменены навигатором-точками —
  см. следующий раздел).
- **Тематическая модалка подтверждения** (`render.confirmDialog`) вместо
  браузерного `confirm()` — используется и при выходе из теста, и при
  удалении главы/вопроса в admin.js.
- **Возврат туда, откуда начали тест** (`state.originScreen` /
  `quiz.returnToOrigin`) при выходе из незавершённого теста — а не всегда
  в корень меню. Экзамен как и раньше стартует прямо с меню, так что для
  него это ведёт себя как обычный возврат в меню.

**Билеты** (`tickets` в исходной ветке) — не переносил: это тот же концепт,
что и «вопросы внутри главы», отдельная сущность на бэкенде не нужна.

## Навигатор-точки вместо прогресс-бара и кнопок Prev/Next

Раньше слева был статичный светофор-рейка (три кружка, индикатор общего
"настроения" приложения) — по сути декоративный. Убрал его целиком и
переиспользовал ту же идею предметнее: на экране вопроса теперь ряд точек
сверху (`#q-dots`), по одной на каждый вопрос, вместо прогресс-бара —
работает одинаково в главах/случайном билете/экзамене:

- **пустая** — вопрос ещё не отвечен
- **жёлтая, залитая** — отвечен, но правильность не раскрывается (только
  экзамен — там результат узнаётся лишь в конце, поэтому не может быть
  зелёной/красной ещё во время прохождения)
- **зелёная / красная** — отвечен верно/неверно (главы и случайный билет —
  там ответ раскрывается сразу)
- **кольцо поверх любого цвета** — вопрос, на котором сейчас находишься;
  если он к тому же ещё не отвечен — точка вместо кольца пульсирует
  янтарным (тот же пульс, что раньше был у сигнальной рейки)

Клик по точке — переход к любому вопросу напрямую (не только соседнему,
как было с Prev/Next). Кнопки "← Назад"/"Далее →" убраны полностью —
единственная кнопка на экране вопроса теперь "Завершить", она принудительно
заканчивает тест прямо сейчас (для этого и была нужна — не для обычной
навигации). Стрелки `←`/`→` и цифры на клавиатуре продолжают работать как
раньше — это не "кнопки", их не убирал.

Раньше тест на последнем вопросе завершался автоматически при нажатии
"Далее" — из-за этого можно было случайно закончить тест, попросту пролистав
несколько вопросов не глядя. Теперь `questionNext()` на последнем вопросе
никуда не ведёт — единственный способ закончить тест — явно нажать
"Завершить" (или `Esc` → подтвердить выход, но это уже без сохранения
результата, другое действие).

## Другие баги, найденные и починенные в этом раунде

- **В списке глав у каждой главы было "00"** вместо порядкового номера —
  классическая ловушка `??` с нулём: `raw.order ?? index + 1` не срабатывает,
  если `order` уже `0` (а по умолчанию у **всех** новых глав `order: 0`, см.
  `ChapterCreate` на бэкенде — значит `0 ?? fallback` возвращает `0`, а не
  `fallback`). Бейдж в списке теперь всегда `index + 1` — порядковая позиция
  в уже отсортированном бэкендом списке, а не поле `order`.
- **Кнопка ✏️ у главы показывалась всегда**, даже без включённого режима
  редактирования (переключался только показ ❌). Теперь обе кнопки
  появляются только вместе, по одному и тому же переключателю.
- **`<select>` с ролью при выдаче лицензии был белым** — `<option>` не
  наследует цвет/фон от родительского `<select>` во всех движках, нужно
  было явное правило `select option { background; color; }`.

## Не реализовано / упрощено

- Ошибки в формах редактирования (главы/вопросы/лицензии) показываются
  через `alert()` — работает, но грубовато; при желании заменить на
  инлайн-текст в модалке, форма уже это позволяет
- Самоподписанный HTTPS-сертификат для прод-адреса `API_BASE_URL` не
  настраивался — сейчас клиент рассчитан на `http://localhost:8000`
